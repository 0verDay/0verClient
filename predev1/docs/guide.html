Part 1

用户部分

你拿到的是一个 0verClient.exe，接下来怎么用。

1. 先搞懂一件事：启动器本身不含游戏

这是最容易误解的地方，先记住三句话：

  1. 启动器只是一个客户端。它里面没有任何游戏，必须能访问到一个内容源（一台提供游戏清单和文件的服务器）。
  2. 游戏列表来自服务器，不是内置的。启动器启动时拉取一个叫 index.json 的索引文件，界面上显示哪些游戏完全由它决定。
  3. 内容源必须一直开着。服务器那边一停，游戏库立刻变空并提示「读取索引失败」——这不是客户端坏了。
「内容源」是什么？就是一台跑着 0verClient 内容服务（或任何静态 Web 服务器）的机器， 上面放着一个站点目录。index.json 是这个目录的入口。 发布者会给你一个形如 http://服务器地址:8787/index.json 的地址 —— 这就是你要填的东西。

2. 运行客户端

2.1 直接双击

下载到的客户端通常是一个文件夹，里面至少有：

文件作用
0verClient.exe启动器本体，双击它
launcher.json预设配置（如果发布者给了）。里面写好了服务器地址，让你不用手填
run-client.cmd可选启动脚本。只有零依赖打包版才需要，双击它等于双击 exe

双击 0verClient.exe 即可。窗口是半透明圆角的，左侧是导航栏。

2.2 界面结构

位置内容
左侧导航游戏库 / 下载 / 设置 三个页面
左下角显示启动器版本号和当前通道（一般是 latest）
右上角刷新游戏库 按钮（常驻，任何时候都能点）

第一次打开时，如果内容源没配置好或没启动，中间会显示错误提示和一个重试按钮。这是正常的，去「设置」页配好地址再刷新即可。

为什么第一次打开可能什么都没有？因为启动器启动时就会去拉索引。 如果你还没填服务器地址（且发布者也没给 launcher.json），它默认指向 http://127.0.0.1:8787/index.json —— 那是开发者本机调试用的地址，你这边当然是空的。 直接去「设置」页改成发布者给你的地址即可。

3. 选择服务器（设置页）

点左侧「设置」。这里有三个字段，全部与「连哪台服务器」有关。

3.1 内容源索引地址

http://你的服务器地址:8787/index.json

这就是选服务器的地方。发布者应该会给你这个地址。填完点「保存」。

3.2 允许的主机白名单

填服务器的主机名或 IP，只填主机，不要带 http:// 和端口：

203.0.113.10
:: 多个用逗号分隔
203.0.113.10, cdn.example.com

留空表示不限制 https 主机（仍然只允许 https）。

3.3 允许明文 http

一个复选框，仅调试用。

明文 http 需要「两个条件同时满足」才会被放行：
  1. 勾上「允许明文 http」这个开关
  2. 并且该主机出现在上面的白名单里
少任何一个都会被拒绝。这是故意设计的 —— 避免一个开关不小心把所有主机都放开。

例外：本机回环地址（127.0.0.1 / localhost）天然允许明文 http， 不需要勾开关也不需要加白名单。这是为了方便本地调试。

3.4 三种典型场景

场景索引地址白名单明文 http
发布者给了预设（launcher.json） 什么都不用做，直接刷新游戏库即可
自建 http 服务器（最常见） http://IP:8787/index.json IP ☑ 勾上
https 服务器（正式环境） https://域名/index.json 可留空 ☐ 不用勾
保存之后一定要点「刷新游戏库」。保存只是写入了配置，不会自动重新读索引。 设置页和游戏库页右上角都有刷新按钮。

4. 下载与安装游戏

4.1 卡片上那颗按钮会变

游戏库里的每个游戏是一张卡片，卡片上只有一个按钮，它的文字随状态变化：

按钮文字含义点它会怎样
安装未安装开始下载
取消正在下载中断安装（已下载的部分会保留）
启动已安装运行游戏
结束游戏运行中强制结束游戏进程
重试安装失败重新尝试安装

卡片上还会显示状态文字，例如「未安装 · 可获取 v1.0.0」「已安装 v1.0.0」「运行中」「下载中 42%」。

4.2 下载过程

点「安装」后会显示进度条，同时给出：

  • 已完成的文件数 / 总文件数
  • 已下载字节 / 总字节
  • 当前速度（例如 512 KB/s）
  • 预计剩余时间

4.3 断点续传：中断了不用从头再来

这是个实用特性。即使中途关掉客户端或断网，再次点「安装」会从断点继续，而不是重新下载整个游戏。

原理是每个文件都会先写成 xxx.part，续传时向服务器发 Range 请求只要剩下的部分。 只有校验失败时才会删掉重来。

服务器不支持 Range 也能用，只是退化成整文件重下，不能续传。 官方的内容服务是支持 Range 的。

4.4 「下载」页是什么

左侧第二个页面。它把正在安装或已安装但还没启动的游戏单独列出来， 方便你在游戏很多的时候不用在游戏库里翻找。卡片操作和游戏库完全一样。

4.5 安装是「事务性」的

安装过程中会先写到临时目录，全部文件校验通过后才一次性切换到位。所以：

  • 下载失败绝不会破坏你已经装好的旧版本
  • 不会出现「装到一半、目录半新半旧」的状态
  • 重复安装同一个版本时，已存在的文件会被直接复用（瞬间完成、不重复下载）

5. 启动与结束游戏

安装完成后按钮变成「启动」，点击即运行。游戏运行期间：

  • 按钮变成「结束」，可随时强制结束
  • 状态显示「运行中」
  • 游戏退出后，会自动记录本次游玩时长和累计时长
  • 游戏异常退出（非正常退出码）会显示「游戏异常退出」并标记出来

设置里还有一个 KillGamesOnExit 选项（默认关闭）：打开后，关闭启动器时会一并结束它启动的游戏。

6. 文件都在哪里

所有数据都在 %LOCALAPPDATA%\0verClient\ 下，不污染系统目录：

路径内容
%LOCALAPPDATA%\0verClient\settings.json你的设置（索引地址、白名单、开关）
%LOCALAPPDATA%\0verClient\games\<游戏id>\安装好的游戏文件
%LOCALAPPDATA%\0verClient\logs\0verclient-<日期>.log运行日志，出问题时看这个
%LOCALAPPDATA%\0verClient\state\已安装记录、游玩时长

「设置」页最下方有运行信息区域，三个「打开」按钮分别打开数据目录、游戏目录、日志目录 —— 不用手敲路径。

想「重置成发布者的预设」怎么办？删掉 %LOCALAPPDATA%\0verClient\settings.json，重启客户端。 预设 launcher.json 只在你没有自己的 settings.json 时才生效， 一旦你在设置页点过保存，就以你自己的为准，预设不会再覆盖你的修改。

7. 用户常见问题

游戏库是空的 / 提示「读取索引失败」

最常见的原因是服务器那边的内容源没在运行，或者地址填错了。按顺序检查：

  1. 用浏览器打开你的索引地址（例如 http://IP:8787/index.json）。能看到一段 JSON，说明服务器没问题
  2. 看不到 → 找发布者确认内容源是否开着
  3. 能看到但客户端仍然空 → 检查设置页的地址有没有填错端口，然后点「刷新游戏库」

提示「拒绝明文 http」

你的地址是 http:// 而不是 https://。去设置页同时做两件事：勾上「允许明文 http」+ 把主机加进白名单，然后保存并刷新。

提示「URL 主机不在白名单内」

白名单填的不是当前这个地址的主机。注意白名单里不要写 http:// 和端口。

提示「内容源地址自相矛盾」

索引文件里的下载地址指向 127.0.0.1，也就是你自己这台电脑。 这几乎总是发布者拿「本地测试包」当「服务器包」发出去了。联系发布者重新发布。

提示「清单哈希校验失败」

服务器上的文件不完整（常见于只拷了 index.json，没拷 manifest.json 或游戏文件）。 这是客户端在保护你 —— 它拒绝安装内容对不上的东西。联系发布者。

一屏弹窗 / 客户端卡死

这是早期版本的绑定 bug，已在 predev1 修复。更新到最新客户端即可。

还是不行

打开日志目录里最新的 .log 文件，里面有每一步的详细记录（拉取索引、每个文件的下载结果、错误堆栈）。把日志给发布者看，基本能定位。

8. 开发环境

8.1 需要什么

项要求说明
操作系统Windows客户端是 WPF，只能跑 Windows
.NET SDK10.0.401global.json 已钉死；配了 rollForward: latestFeature，所以 10.0.4xx 都可以
Git任意版本拉代码
PowerShell5.1+系统自带，构建脚本用它

确认环境：

dotnet --version        :: 应显示 10.0.401 之类

8.2 从零开始

git clone https://github.com/0verDay/0verClient.git
cd 0verClient\predev1
.\run-demo.ps1 -SmokeTest

这一条命令会：编译 6 个工程 → 起一个本地内容源（http://127.0.0.1:8787）→ 跑 43 项引擎自检 → 打开启动器界面。 看到游戏卡片就说明整条链路通了，可以点「安装」→「启动」。

零 NuGet 依赖。7 个工程没有一个 PackageReference， 普通的 dotnet build 完全不联网，HttpClient / SHA256 / ECDsa / System.Text.Json / Process 全在 BCL 里。 只有 AOT / 自包含发布才需要联网拉包（见 9.3）。

9. 编译客户端与服务端

9.1 先分清两件事（最重要）

「打包」在本项目里指两件完全不同的事，混起来就会一头雾水：

打包程序打包内容
是什么把源码编译成 exe把游戏目录变成静态站点（索引 + 清单 + 文件）
命令.\build-dist.ps1Publish.exe 或 .\publish-testpack.ps1
产物dist\server\、dist\client\build\site\
拷到哪服务端 → 服务器；客户端 → 玩家服务器上的 site\ 目录
什么时候做改了代码之后加了游戏 / 更新版本之后
两者频率完全不同：程序打包一次能用很久；内容每上一个游戏、每更新一次版本都要重打。
所以「加了个游戏」不需要重新编译 exe，只需要重打站点。

9.2 两条核心命令

cd C:\...\0verClient\predev1

:: 服务端：原生单文件，约 2.2 MB，目标机什么都不用装
.\build-dist.ps1 -Target server -Aot

:: 客户端（二选一）
.\build-dist.ps1 -Target client                            :: 约 280 KB，玩家需装 .NET 10 桌面运行时
.\build-dist.ps1 -Target client -SelfContained -SingleFile :: 约 59 MB，玩家什么都不用装
为什么服务端和客户端不合成一条命令？ 因为客户端是 WPF，既不能 NativeAOT 也不能裁剪（SDK 直接拒绝，报 NETSDK1168）， 只能用自包含模式，而且必须加 -SingleFile 压缩才小；服务端则用 AOT 最划算。 两个目标的最优解不同，所以分开跑。
（脚本会拦住你：-Aot 配 -Target both 会直接报错并说明原因。）

9.3 五种打包模式，怎么选

模式命令体积目标机要求需联网一次
AOT（服务端推荐） -Target server -Aot 约 2.2 MB 无 是
裁剪 -Trimmed 约 12–20 MB (估算) 无 是
框架依赖（默认） -Target server 255 KB 装 .NET 10 运行时 否
自包含 -SelfContained 约 70 MB 无 是
便携（离线） -Portable 约 77 MB 无 否

什么时候换模式：

  • AOT 报错（缺 MSVC 或 nuget 不可达）→ 先用 -Portable 顶上，体积大但一定能用
  • 目标服务器本来就装了 .NET 10 运行时 → 用框架依赖，只有 255 KB
  • 开发机不能上网 → 用 -Portable（直接复制本机已装的运行时，完全离线）

9.4 服务端产物

文件是什么必需?
0verClient.Server.exe原生单文件程序，约 2.2 MB。AOT 模式下无 runtimeconfig、无 deps.json、无任何 DLL✅
run-server.cmd启动脚本，参数已预填：--root "%~dp0site" --port 8787 --add-firewall-rule✅
默认会剥掉 .pdb。NativeAOT 的调试符号可能比程序本身还大 （实测 9.7 MB 符号 vs 2.1 MB exe），服务器上用不到。需要排查崩溃时加 -KeepSymbols。

9.5 客户端产物

文件是什么
0verClient.exe启动器本体
launcher.json预设：服务器地址、白名单、是否允许明文 http。玩家第一次运行自动生效
run-client.cmd便携模式的启动脚本（设置 DOTNET_ROOT 指向内嵌运行时）
runtime\内嵌的 .NET 运行时（仅便携/自包含模式）

launcher.json 的地址来自 ServerIP.txt：

{
    "indexUrl":          "http://YOUR_SERVER_IP:8787/index.json",
    "channel":           "latest",
    "allowedHosts":      "YOUR_SERVER_IP",
    "allowInsecureHttp": true
}

端口不是 8787 时打包时指定：

.\build-dist.ps1 -Target client -SelfContained -SingleFile -ServerUrlPort 8788
launcher.json 只在玩家还没有自己的设置时生效。他一旦在设置页点过「保存」， 就以 %LOCALAPPDATA%\0verClient\settings.json 为准，预设不会覆盖他的修改。

9.6 为什么客户端这么大

171 MB 的构成（实测，非单文件模式）：

组成大小说明
Microsoft.NETCore.App76.3 MB.NET 基础运行时
Microsoft.WindowsDesktop.App94.4 MBWPF 运行时。其中约 22 MB 是 WinForms（我们完全没用到），但框架整体分发，取不出来
我们自己的程序约 0.3 MBexe + Core.dll + 两个 json

所以客户端体积下界由「要不要玩家装运行时」决定：要 → 280 KB；不要 → 59 MB（单文件压缩）。

9.7 服务端的运行参数

0verClient.Server.exe --root <站点目录> [选项]

必需:
  --root <dir>            由 Publish.exe 产出的站点目录（index.json 必须在它根下）

选项:
  --port <n>              监听端口（默认 8787）
  --bind <ip>             绑定地址（默认 0.0.0.0 = 所有网卡；127.0.0.1 = 仅本机）
  --throttle-kbps <n>     每连接限速（默认 0 = 不限速）
  --idle-timeout-ms <n>   丢弃不发请求的空连接（默认 5000）
  --add-firewall-rule     顺带放行 Windows 防火墙端口（需管理员）
  --help                  显示帮助
--idle-timeout-ms 不是可有可无的：浏览器和 HTTP 客户端习惯先建立「预连接」再决定发不发请求， 没有空闲超时的话，一个空连接就能把服务卡死 —— 端口仍显示 LISTENING、进程也活着，但对所有人都不再响应。

10. 本地验证

10.1 一键 demo

.\run-demo.ps1                  :: 正常 demo
.\run-demo.ps1 -SmokeTest       :: 先跑无头自检（43 项），再开界面
.\run-demo.ps1 -DropAfter       :: 服务器中途掐断连接，验证断点续传
.\run-demo.ps1 -NoThrottle      :: 不限速
.\run-demo.ps1 -SkipBuild       :: 跳过编译

10.2 三层验证，各管各的

验证命令覆盖什么
界面自检 0verClient.exe --selfcheck 把全部 XAML 和游戏卡片模板真正实例化一遍。退出码 0 = 通过
引擎自检 SmokeTest.exe --index <url> --fresh --verbose 无头跑完整安装链路，43 项检查
服务器自检 check-server.ps1（在服务器上跑） 六层健康检查

引擎自检展开：

dotnet run --project tools\SmokeTest -- `
  --index http://127.0.0.1:8787/index.json --fresh --verbose --launch-check
:: 期望结尾：全部通过（43 项检查）
改过 XAML 之后必须跑 --selfcheck。 XAML 的绑定模式错误是运行时才抛的，编译期 0 error。典型例子： ProgressBar.Value 的元数据是 BindsTwoWayByDefault， 绑到只读属性时不写 Mode=OneWay 就会每张卡片抛一次 XamlParseException； 而卡片只在游戏库非空时才渲染，所以内容源没起来时这个错误会一直躲着。

容易被忽略的这类属性还有：TextBox.Text、CheckBox.IsChecked、ListBox.SelectedIndex。

11. 添加新游戏（打包内容）

11.1 一步到位

.\tools\Publish\bin\Debug\net10.0-windows\Publish.exe `
  --game "D:\Games\我的游戏" --id mygame --name "我的游戏" `
  --version 1.0.0 --base-url http://YOUR_SERVER_IP:8787 --out build\site

--game 指向游戏目录，会把里面的文件递归全部纳入。

11.2 完整参数

参数必需说明
--game <folder>✅游戏文件所在目录（递归）
--id <gameId>✅稳定的游戏 id，同时用作目录名，例如 testpack
--out <siteDir>✅站点输出根目录（不存在会创建；可重复运行）
--base-url <url>✅站点目录对外的公开 URL 前缀，例如 http://IP:8787
--name <text>显示名（默认同 --id）
--version <text>版本号（默认 1.0.0）
--channel <name>通道名（默认 latest）
--summary <text>卡片上的简短描述
--accent <#RRGGBB>卡片主题色（默认 #4C8DFF）
--tags <a,b,c>逗号分隔的标签
--notes <text>更新说明
--launch <relpath>启动入口；省略时自动探测 .exe/.cmd/.bat
--launch-arg <value>启动参数，可重复写多次
--min-launcher <ver>最低启动器版本（默认 0.1.0）
--keep-pdb保留 .pdb（默认排除）

11.3 加第二个游戏不会覆盖第一个

index.json 是合并不是覆盖。用同一个 --out 再跑一次、换个 --id， 新游戏会追加进去，已有的游戏原样保留。游戏可以一个一个加。

:: 第一个
Publish.exe --game "D:\Games\A" --id gamea --name "游戏A" --version 1.0.0 `
  --base-url http://YOUR_SERVER_IP:8787 --out build\site

:: 第二个（游戏A 不受影响）
Publish.exe --game "D:\Games\B" --id gameb --name "游戏B" --version 1.0.0 `
  --base-url http://YOUR_SERVER_IP:8787 --out build\site

用同一个 --id 再跑一次则是更新那个游戏（发布新版本）。

11.4 发布新版本 / 通道

:: 把 mygame 更新到 1.1.0
Publish.exe --game "D:\Games\我的游戏" --id mygame --name "我的游戏" `
  --version 1.1.0 --notes "修了几个 bug" `
  --base-url http://YOUR_SERVER_IP:8787 --out build\site

:: 发到 beta 通道，玩家只有把设置里的通道改成 beta 才会拿到
Publish.exe --game "D:\Games\我的游戏-test" --id mygame --version 1.2.0-beta `
  --channel beta --base-url http://YOUR_SERVER_IP:8787 --out build\site

一个游戏可以有多个通道（latest / beta …），每个通道各自指向一个版本的清单。 客户端默认读 latest。

11.5 站点结构长什么样

build\site\
    index.json                        根索引：有哪些游戏、清单地址 + 清单 sha256
    games\
        mygame\
            manifest.json             文件清单：路径 / 大小 / sha256 / URL、启动方式
            files\                    游戏文件本身（按原目录结构）
                ...

两层清单各有分工，都是唯一真相源，客户端不硬编码任何游戏信息：

文件回答什么问题变动频率
index.json有哪些游戏？每个通道当前版本的清单在哪、清单的 sha256 是多少？加游戏时变
manifest.json这个版本由哪些文件组成（路径/大小/sha256）？怎么启动？最低启动器版本？每个版本一份，不可变

11.6 新增游戏后的完整流程

  1. 用 Publish.exe 打包进 build\site（加上文）
  2. 把整个 build\site 传到服务器，覆盖服务器上的 site\
  3. 玩家点「刷新游戏库」，新游戏就出现了
不需要重新编译服务端。服务端只是把目录用 HTTP 提供出去，站点内容变了它自动就提供新的。 也不需要重启服务端进程。

12. 上传服务端到云服务器

12.1 整体链路

本机                                          云服务器
────────────────────────────────────────      ─────────────────────────────────
1. dotnet build / build-dist.ps1              4. 起内容源（服务端 exe 或 serve-site.ps1）
2. publish-testpack.ps1 / Publish.exe         5. 放行 Windows 防火墙  +  云安全组
3. 传 dist\server + build\site  ──────────►   6. 验证：浏览器打开 index.json

12.2 一次性：写服务器地址

新建 predev1\ServerIP.txt，里面只写一行公网 IP（照 ServerIP.txt.example）：

203.0.113.10
这个文件不进版本库（已被 .gitignore 排除），因为它是你的私有地址。 它同时被 publish-testpack.ps1、build-dist.ps1、check-server.ps1 读取， 是服务器地址的唯一真相源。

12.3 打包内容（两条路）

:: 路 A：测试包（自带，用来验证整条链路）
.\publish-testpack.ps1

:: 路 B：真正要上的游戏
.\tools\Publish\bin\Debug\net10.0-windows\Publish.exe `
  --game "D:\Games\我的游戏" --id mygame --name "我的游戏" `
  --version 1.0.0 --base-url http://YOUR_SERVER_IP:8787 --out build\site

publish-testpack.ps1 会读 ServerIP.txt → 编译 Publish → 用正确的 --base-url 打包 → 把剩下的步骤打印在屏幕上 → 最后探测一次服务器是否已能连上。

--base-url 会被以绝对 URL 写死进 index.json 和 manifest.json。 所以地址或端口一变就必须重新打包。
给服务器打的包在本地托管必然失败，反之亦然 —— 这不是 bug，是内容寻址的设计代价。
publish-testpack.ps1 每次都清空重建 build\site，就是为了不让旧地址残留下来。

想先在本地验证打包结果，用 -Local（URL 指向 127.0.0.1）：

.\publish-testpack.ps1 -Local -SkipCheck
.\tools\serve-site.ps1 -Root build\site -Port 8787 -Bind 127.0.0.1

12.4 上传到服务器

最终服务器上应该只有这些：

C:\0verclient\
    0verClient.Server.exe      ← dist\server
    run-server.cmd             ← dist\server
    site\
        index.json
        games\<id>\manifest.json
        games\<id>\files\...

传输方式随你：远程桌面剪贴板（文件小的话）、scp、或者 mstsc 挂载本地磁盘后从 \\tsclient\C\... 复制（几个 GB 的游戏用这个）。

只用 PowerShell 也行。仓库里的 tools\serve-site.ps1 是零安装的静态服务器 （Windows Server 自带 PowerShell 就能跑，支持 Range），可以完全替代 0verClient.Server.exe。两种方式二选一即可。

12.5 在服务器上起服务

用服务端 exe（推荐，管理员身份运行以便自动加防火墙规则）：

:: 双击 run-server.cmd，或手动：
.\0verClient.Server.exe --root C:\0verclient\site --port 8787 --add-firewall-rule

或用 PowerShell 版（同样管理员）：

powershell -ExecutionPolicy Bypass -File C:\0verclient\serve-site.ps1 `
  -Root C:\0verclient\site -Port 8787 -AddFirewallRule

期望看到：

0verClient content server is running
  root        : C:\0verclient\site
  listening   : 0.0.0.0:8787 (all network interfaces)
  idle timeout: 5000 ms (a connection that sends no request is dropped)
这个窗口不要关。关掉内容源就停了，玩家那边游戏库立刻变空。
注意区分：叉掉远程桌面窗口（断开连接）→ 进程还在； 注销 / 重启服务器 → 进程没了，必须重新运行。
想长期常驻：用计划任务开机自启，或换 IIS。

12.6 两层防火墙，都要开

这是最容易卡住的一步 —— 机器上的 Windows 防火墙和云厂商的安全组是两回事：

层在哪开怎么做
Windows 防火墙 服务器上 启动时加 --add-firewall-rule（管理员）自动加；或手动 netsh
云安全组 云控制台 找到实例 → 防火墙 / 安全组 → 添加规则：协议 TCP、端口 8787、来源 0.0.0.0/0

腾讯云轻量应用服务器在「实例 → 防火墙」里加。

12.7 验证

第 1 步：在你本机浏览器打开：

http://YOUR_SERVER_IP:8787/index.json

能看到一段 JSON，就说明服务器 + Windows 防火墙 + 云安全组三层全通。

第 2 步：在服务器上跑六层健康检查（它会一次把六层全查完并告诉你哪层坏了）：

powershell -ExecutionPolicy Bypass -File C:\0verclient\check-server.ps1

全通时打印 EVERYTHING ON THIS MACHINE IS FINE，并告诉你问题在云安全组。

访问不了时，按从里到外的顺序查：

层在哪查命令失败说明
1 文件服务器dir C:\0verclient\site目录层级错了 / 没拷
2 进程服务器netstat -ano | findstr :8787内容源窗口被关了
3 本机 HTTP服务器curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:8787/index.json服务死了或 -Root 指错
4 清单 URL服务器Select-String -Path C:\0verclient\site\index.json -Pattern '127\.0\.0\.1|YOUR_SERVER_IP'拷的是 -Local 包
5 机器防火墙服务器Get-NetFirewallRule -DisplayName "*0verClient*"没加规则
6 云安全组控制台实例 → 防火墙没放行 8787
第 3 层能通、但你本机打不开 → 问题一定在第 5 或第 6 层，不用再怀疑前四层。

12.8 最后：让玩家连上

把客户端和 launcher.json 一起发给玩家（打包时若 ServerIP.txt 存在， 预设地址会自动写好），他就不需要做任何设置。 没给预设的话，让他按第 3 节手填地址。

迁移到另一台服务器：拷 dist\server 过去 → 双击 run-server.cmd → 放行新机器的 8787。若 IP 变了，改 ServerIP.txt 后重新 publish-testpack.ps1， 再把 build\site 传过去（清单里是绝对 URL，地址变了必须重打）。

13. 开发常见问题

dotnet build 0verClient.slnx 失败，但显示 0 个错误

这是环境问题，不是项目问题。根因通常是 .NET SDK 安装不完整 —— 缺 Sdks\Microsoft.NET.SDK.WorkloadAutoImportPropsLocator 和 Sdks\Microsoft.NET.SDK.WorkloadManifestTargetsLocator 两个目录， restore 阶段会在 _FilterRestoreGraphProjectInputItems 静默失败。
解决：修复 / 重装 .NET SDK 10.0.401。
日常开发用 .\run-demo.ps1 或逐个编译 csproj 即可绕开（脚本本来就是这么做的，报错也更直接）。

AOT 打包报 MSB3073 / link.exe / vcruntime

缺 MSVC 工具链。打开 Visual Studio Installer → 修改 → 勾选「使用 C++ 的桌面开发」（含 Windows SDK）。

AOT 打包报 NU1301 / NU1100

拉不到包。NU1100 无法解析 通常是 nuget.config 里没有包源； NU1301 Unable to load the service index 是网络/代理问题。 先确认能访问 https://api.nuget.org/v3/index.json。
注：nuget.config 刻意保留了官方源 —— 曾经写成 <clear /> 时， AOT restore 会在 0.6 秒内以 NU1100 失败，快得看不出是「没配源」，很容易误判成网络问题。

重新打包会不会把 dist\server\site 里的游戏删掉

不会。打包脚本会保留 site 子目录（只清理程序文件）—— 因为 run-server.cmd 默认就指向 %~dp0site， 每次构建都清空会静默删掉几个 GB 的游戏文件。

-SelfContained 和 -Portable 的区别

-SelfContained 从 nuget.org 下载运行时（需联网一次）； -Portable 直接复制本机已装的运行时（完全离线）。 两者产出的包都能在没装 .NET 的机器上直接跑。

客户端改了设置但没生效

玩家已有的 %LOCALAPPDATA%\0verClient\settings.json 优先于预设。删掉它即可回到预设。

仓库的编辑约定（三个坑）

  1. run-demo.ps1 必须保持纯 ASCII。Windows PowerShell 5.1 会按 ANSI 代码页 解码无 BOM 的 .ps1，中文变乱码会直接破坏语法。控制台工具同理（所以 Publish 输出是英文）。
  2. PowerShell 里别把参数名当局部变量名。[switch]$SmokeTest 会把 $SmokeTest 约束成 SwitchParameter，再写 $smokeTest = <路径> 就会抛类型转换错误。
  3. XAML 里绑定到只读属性必须显式写 Mode=OneWay。见 10.2 的说明， 改完 XAML 一定跑一次 --selfcheck。

要推 GitHub 前怎么清干净

.\clean.ps1 -WhatIf      :: 先看会删什么
.\clean.ps1              :: 真删

.gitignore 已覆盖 bin/ obj/ dist/ build/ artifacts/ .dotnet/ .nuget/ .tmp/ .vs/ ServerIP.txt， 也就是所有产物、缓存和本机配置都不会进仓库。 行尾策略由根目录的 .gitattributes 固定（统一 LF，批处理 CRLF）。

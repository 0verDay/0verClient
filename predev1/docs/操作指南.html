1. 先分清两件事（最重要）

「打包」在 0verClient 里指两件完全不同的事，混在一起就会一头雾水：

打包程序打包内容
是什么 把源代码编译成 exe（服务端程序、客户端程序） 把游戏目录变成一个静态站点（索引 + 清单 + 文件）
命令 .\build-dist.ps1 .\publish-testpack.ps1 或 Publish.exe
产物 dist\server\、dist\client\ build\site\
拷到哪 服务端 → 服务器；客户端 → 玩家 服务器上的 site\ 目录
什么时候做 改了代码之后 加了游戏、更新了游戏版本之后
两者的频率完全不同。 程序打包一次可以用很久；内容则是每上一个游戏、每更新一次版本都要重打一次。
所以「加了个游戏」不需要重新编译 exe，只需要重打站点。

2. 一次性准备

正常情况下什么都不用装 —— Visual Studio 2026 和 .NET 10 SDK 已经就位，AOT 需要的 MSVC 工具链也在。

唯一会「下载东西」的是第一次 AOT 打包（需要 ILCompiler 等包，约 450 MB）。已经下过一次之后就一直可用，之后完全离线。

确认一下环境：

cd C:\Users\yy197\Documents\GitHub\0verClient\predev1
dotnet --version        :: 应显示 10.0.401 之类

3. 日常最常用：两条命令

cd C:\Users\yy197\Documents\GitHub\0verClient\predev1

:: 服务端：原生单文件，约 2.2 MB，目标机什么都不用装
.\build-dist.ps1 -Target server -Aot

:: 客户端（二选一）
.\build-dist.ps1 -Target client                            :: 280 KB，玩家需装 .NET 10 桌面运行时
.\build-dist.ps1 -Target client -SelfContained -SingleFile :: 59 MB，玩家什么都不用装
为什么不合成一条命令？ 因为客户端的 WPF 界面不支持 NativeAOT（也不能裁剪）， 只能用自包含模式 —— 而且必须加 -SingleFile 压缩才小；而服务端用 AOT 最划算。 两个目标的最优解不同，所以分开跑。
（脚本会拦住你：-Aot 配 -Target both 会直接报错并说明原因。）

4. 打包服务端（详解）

4.1 推荐命令

.\build-dist.ps1 -Target server -Aot

✅ 期望输出：

  mode        : NativeAOT (native single exe, no runtime shipped)
==> publishing server -> dist\server
  0verClient.Server net10.0 win-x64 已成功 (x.x 秒) → dist\server\
  stripped 9.xx MB of debug symbols (-KeepSymbols keeps them)
    -> 2.xx MB in dist\server

4.2 产物是什么

文件是什么必需?
0verClient.Server.exe原生单文件程序，约 2.1 MB。无 runtimeconfig、无 deps.json、无任何 DLL✅
run-server.cmd启动脚本，参数已预填：--root "%~dp0site" --port 8787 --add-firewall-rule✅
默认会剥掉 .pdb。 NativeAOT 的调试符号可能比程序本身还大 （实测 9.7 MB 符号 vs 2.1 MB exe），服务器上用不到。需要排查崩溃时加 -KeepSymbols。

4.3 五种模式，怎么选

模式命令体积目标机要求需联网一次
AOT（推荐） -Target server -Aot 约 2.2 MB 无 是
裁剪 -Trimmed 约 12–20 MB (估算) 无 是
框架依赖（默认） -Target server 255 KB 装 .NET 10 运行时 否
自包含 -SelfContained 约 70 MB 无 是
便携（离线） -Portable 约 77 MB 无 否

什么时候换模式：

  • AOT 报错（缺 MSVC、或 nuget 不可达）→ 先用 -Portable 顶上，体积大但一定能用
  • 目标服务器本来就装了 .NET 10 运行时 → 用框架依赖，只有 255 KB
  • 开发机不能上网 → 用 -Portable（复制本机已装的运行时）

5. 打包客户端（详解）

5.1 推荐命令

:: 最小：约 280 KB。前提是玩家装过 .NET 10 桌面运行时
.\build-dist.ps1 -Target client

:: 零依赖：一个 59 MB 的 exe，玩家什么都不用装
.\build-dist.ps1 -Target client -SelfContained -SingleFile

5.2 产物是什么

文件是什么
0verClient.exe启动器本体
launcher.json预设：服务器地址、白名单、是否允许明文 http。玩家第一次运行自动生效，不用手打地址
run-client.cmd便携模式的启动脚本（设置 DOTNET_ROOT 指向内嵌运行时）
runtime\内嵌的 .NET 运行时（便携/自包含模式才有）

launcher.json 的内容长这样，地址来自 ServerIP.txt：

{
    "indexUrl":          "http://YOUR_SERVER_IP:8787/index.json",
    "channel":           "latest",
    "allowedHosts":      "YOUR_SERVER_IP",
    "allowInsecureHttp": true
}
launcher.json 只在玩家还没有自己的设置时生效。他一旦在设置页点过「保存」， 就以 %LOCALAPPDATA%\0verClient\settings.json 为准，预设不会覆盖他的修改。

端口不是 8787 时，打包时指定：

.\build-dist.ps1 -Target client -SelfContained -SingleFile -ServerUrlPort 8788

5.3 为什么客户端这么大，怎么变小

171 MB 的构成（实测）：

组成大小说明
Microsoft.NETCore.App76.3 MB.NET 基础运行时
Microsoft.WindowsDesktop.App94.4 MBWPF 运行时。其中约 22 MB 是 WinForms（我们完全没用到），但框架是整体分发的，取不出来
我们自己的程序约 0.3 MBexe + Core.dll + 两个 json

WPF 既不能裁剪也不能 AOT —— SDK 会直接拒绝（实测报错）：

error NETSDK1168: WPF is not supported or recommended with trimming enabled.

5.4 两个让它变小的办法（都已实测）

方案命令传输体积磁盘占用玩家要装东西吗
框架依赖（推荐） -Target client 约 280 KB 约 280 KB 要装 .NET 10 桌面运行时（一次性）
单文件 + 压缩 -Target client -SelfContained -SingleFile 59 MB 约 67 MB 不用
自包含文件夹 / 便携 -Target client -Portable 171 MB 171 MB 不用
怎么选：
  • 玩家能装一次运行时 → 用框架依赖，只有 280 KB。运行时缺失时程序会自己打印官方下载链接。
  • 必须零依赖 → 用单文件 + 压缩，59 MB（首次启动多花约 9 秒解压 8 MB 原生库）。
不再推荐 -Portable 与文件夹形式的 -SelfContained —— 同样零依赖却要 171 MB， 已被单文件压缩版全面取代。这两个模式保留着，服务端某些场景还会用到。

想再小只能换 UI 技术栈（WebView2 宿主约 5 MB / WinForms + AOT），但那要重写整个界面， 和 280 KB 相比不划算。

6. 产物放哪里

6.1 服务端 → 服务器

把 dist\server 里的东西和站点一起放到 C:\0verclient\，最终应该只有这些：

C:\0verclient\
    0verClient.Server.exe      ← dist\server
    run-server.cmd             ← dist\server
    site\
        index.json
        games\<id>\manifest.json
        games\<id>\files\...

然后双击 run-server.cmd（它会自己带上 --root "%~dp0site" --port 8787 --add-firewall-rule）。

服务器上不该有的东西：
  • runtime\ → 只有 -Portable 模式需要，切 AOT 后删掉能省 77 MB
  • *.pdb → 调试符号，服务器上没用
  • 0verClient.Core.dll、*.deps.json、*.runtimeconfig.json → 只有框架依赖模式需要
  • src\ tools\ docs\ samples\ bin\ obj\ dist\ → 源码与产物，服务器上不需要

6.2 客户端 → 玩家

把 dist\client 整个文件夹发给他（压缩成 zip 也行）。里面有 launcher.json，他不需要做任何设置，双击 0verClient.exe 就能看到游戏库。

7. 打包后怎么验证

7.1 客户端

dist\client\0verClient.exe --selfcheck

它会不开窗口地把全部 XAML 和游戏卡片模板实例化一遍。退出码 0 = 通过 （这条专门抓「编译期看不见的绑定模式错误」，建议每次改过界面都跑）。

7.2 服务端

在服务器上双击 run-server.cmd，期望看到：

content: 1 game(s) in index.json
  - testpack  "Server Test Pack"  v1.0.0

============================================================
 0verClient content server
============================================================
  root        : C:\0verclient\site
  listening   : 0.0.0.0:8787 (all network interfaces)
  idle timeout: 2000 ms

它还会自动检查站点地址：如果清单里的 URL 指向 127.0.0.1（用本地地址打的包），会当场警告。

再在服务器上跑一次六层健康检查：

powershell -ExecutionPolicy Bypass -File C:\0verclient\check-server.ps1

期望结尾：EVERYTHING ON THIS MACHINE IS FINE

7.3 整条链路（可选，最彻底）

tools\SmokeTest\bin\Debug\net10.0-windows\SmokeTest.exe `
  --index http://127.0.0.1:8787/index.json --fresh --launch-check

期望：全部通过（43 项检查）

8. 常见问题

AOT 打包报 MSB3073 / link.exe / vcruntime

缺 MSVC 工具链。打开 Visual Studio Installer → 修改 → 勾选「使用 C++ 的桌面开发」（含 Windows SDK）。

AOT 打包报 NU1301 / NU1100

拉不到包。NU1100 无法解析 通常是 nuget.config 里没有包源； NU1301 Unable to load the service index 是网络/代理问题。先确认能访问 https://api.nuget.org/v3/index.json。

重新打包会不会把我放在 dist\server\site 里的游戏删掉

不会。 打包脚本会保留 site 子目录（只清理程序文件），这是刻意设计的 —— 因为 run-server.cmd 默认就指向 %~dp0site。

-SelfContained 和 -Portable 有什么区别

-SelfContained 从 nuget.org 下载运行时（需要联网一次）； -Portable 直接复制本机已装的运行时（完全离线）。两者产出的包都能在没装 .NET 的机器上直接跑。

客户端改了设置但没生效 / 预设不生效

玩家已经有 %LOCALAPPDATA%\0verClient\settings.json 时，以它为谁。想回到预设，删掉那个文件即可（设置页也有索引地址可以手改）。

改了代码之后要做什么

:: 1) 本地快速验证（起内容源 + 启动器）
.\run-demo.ps1

:: 2) 改了界面的话，跑一下无头自检
.\src\0verClient.App\bin\Debug\net10.0-windows\0verClient.exe --selfcheck

:: 3) 打包
.\build-dist.ps1 -Target server -Aot
.\build-dist.ps1 -Target client -SelfContained -SingleFile   :: 或去掉开关出 280 KB 版

要推 GitHub 了，怎么清干净

.\clean.ps1 -WhatIf      :: 先看会删什么
.\clean.ps1             :: 真删
Remove-Item .probe.txt -Force

.gitignore 已覆盖 bin/ obj/ dist/ build/ .dotnet/ .nuget/ .tmp/ .vs/ ServerIP.txt .probe.txt， 也就是所有产物、缓存和本机配置都不会进仓库。

9. 一页速查

:: ── 打包程序 ─────────────────────────────────────
.\build-dist.ps1 -Target server -Aot                         :: 服务端 2.2 MB 原生
.\build-dist.ps1 -Target client                              :: 客户端 280 KB（需 .NET 运行时）
.\build-dist.ps1 -Target client -SelfContained -SingleFile   :: 客户端 59 MB 零依赖

:: ── 打包内容（游戏站点）────────────────────────
.\publish-testpack.ps1                      :: 测试包（读 ServerIP.txt）
.\tools\Publish\bin\Debug\net10.0-windows\Publish.exe `
    --game "D:\Games\某游戏" --id mygame --name "某游戏" `
    --version 1.0.0 --base-url http://YOUR_SERVER_IP:8787 --out build\site

:: ── 本地跑 demo ────────────────────────────────
.\run-demo.ps1

:: ── 验证 ──────────────────────────────────────
dist\client\0verClient.exe --selfcheck                    :: 界面 0 = 通过
tools\SmokeTest\...\SmokeTest.exe --index <url> --fresh     :: 引擎 43 项
check-server.ps1（在服务器上）                              :: 服务器六层

:: ── 清理 ──────────────────────────────────────
.\clean.ps1 -WhatIf
.\clean.ps1
记住这条主线：
build-dist.ps1 打包程序 → exe 进服务器 / 发玩家
Publish.exe / publish-testpack.ps1 打包内容 → build\site 进服务器的 site\
改了代码重打程序；加了游戏只重打内容。

1. 这是什么

一个游戏启动器：客户端从你自己的服务器下载游戏、校验、安装、启动。 启动器本身不含任何游戏，所有游戏信息都来自服务器上一个静态的 index.json —— 没有后端程序、没有数据库、没有账号系统。 

你的电脑                          服务器                        玩家电脑
─────────                        ────────                      ─────────
Publish.exe  ──生成──►  site\  ──上传──►  0verClient.Server.exe
                       index.json                             0verClient.exe
                       games/<id>/manifest.json                   │
                       games/<id>/files/...                       │
                                                                 └─► 下载 → sha256 校验
                                                                     → 原子安装 → 启动

服务器上最终只是一堆静态文件，任何能提供 HTTP（支持 Range）的东西都能托管：本项目的 0verClient.Server.exe、IIS、nginx、腾讯云 COS 都可以。

2. 快速开始（已部署好的情况）

服务器地址：存在本机 ServerIP.txt 里（该文件不进版本库）， 本文档用 YOUR_SERVER_IP 代替。端口 8787，明文 http。
  1. 启动 0verClient.exe
  2. 左侧「设置」页填入：
    字段填什么
    内容源索引地址http://YOUR_SERVER_IP:8787/index.json
    允许的主机白名单YOUR_SERVER_IP
    允许明文 http勾上
  3. 点 保存 → 点 刷新游戏库（游戏库页标题右侧也有一个）
  4. 在卡片上点 安装，装完点 启动

如果 dist\client\launcher.json 存在，上面这些地址是自动填好的 —— 玩家不需要手打。

3. 服务器部署

推荐用本项目自带的服务器程序，它支持 Range（断点续传）、路径穿越防护、空闲连接超时，并且每个连接独立处理，一个空连接不会拖垮服务。

3.1 推荐的目录布局

C:\0verclient\
    0verClient.Server.exe      ← 服务器程序
    run-server.cmd             ← 双击即可启动（参数已预填）
    runtime\                   ← 便携模式下自带的运行时
    site\
        index.json
        games\<id>\manifest.json
        games\<id>\files\...

3.2 启动

cd C:\0verclient
.\run-server.cmd

:: 或者手动指定参数
.\0verClient.Server.exe --root C:\0verclient\site --port 8787 --add-firewall-rule

--add-firewall-rule 需要管理员权限，它会自动执行 netsh advfirewall 放行端口。如果没加成功，服务器会打印手动命令。

启动成功时你会看到：

content: 1 game(s) in index.json
  - testpack  "Server Test Pack"  v1.0.0

============================================================
 0verClient content server
============================================================
  root        : C:\0verclient\site
  listening   : 0.0.0.0:8787 (all network interfaces)
  idle timeout: 5000 ms (a connection that sends no request is dropped)
  concurrency : one thread per connection

  Local test  : http://127.0.0.1:8787/index.json
  From outside: http://<this machine's public IP>:8787/index.json
启动时会直接列出 index.json 里的游戏数量。如果清单里的地址指向 127.0.0.1（用本地地址打的包），它会当场警告 —— 这能省掉一轮"游戏库为什么是空的"排查。

3.3 放行云安全组

腾讯云控制台 → 轻量应用服务器 → 你的实例 → 防火墙 → 添加规则：

协议 TCP / 端口 8787 / 来源 0.0.0.0/0
机器上的 Windows 防火墙和云安全组是两回事，两边都要开。 --add-firewall-rule 只管机器那一半。

3.4 验证

:: 在服务器上
(Invoke-WebRequest http://127.0.0.1:8787/index.json -UseBasicParsing -TimeoutSec 5).StatusCode
:: 应该是 200

然后在你自己的电脑浏览器里打开 http://服务器IP:8787/index.json，看到 JSON 就通了。

3.5 服务器上最终应该有什么

用 NativeAOT 打包时，服务器上只需要下面三样东西：

路径是什么大小
C:\0verclient\0verClient.Server.exe服务器程序约 2.1 MB
C:\0verclient\run-server.cmd启动脚本（参数已预填）小于 1 KB
C:\0verclient\site\index.json + games\<id>\manifest.json + games\<id>\files\...站点内容大小

可选的两样（出问题时省事，不是必需）：

文件用途
check-server.ps1六层健康检查
serve-site.ps1零安装的备选内容源（不想用 exe 时）
服务器上不应该有这些东西：
不该有为什么
*.pdb调试符号。NativeAOT 的符号可能比程序本身还大（实测 9.7 MB vs 2.1 MB）。打包现在已默认剥掉
runtime\只有 -Portable 模式需要。改用 AOT 后可以删掉，能省 77 MB
0verClient.Core.dll、.deps.json、.runtimeconfig.json只有框架依赖模式需要。AOT 版是单个原生 exe，这些都不需要
src\、tools\、docs\、samples\、bin\、obj\、dist\源码与产物，服务器上不需要
.NET SDK / .NET 运行时AOT 版不依赖任何已安装组件

4. 客户端分发

dist\client\ 整个文件夹就是玩家需要的东西。里面：

  • 0verClient.exe —— 启动器
  • launcher.json —— 预设：写好服务器地址、白名单、是否允许明文 http。玩家第一次运行时自动生效，不需要手打地址
  • run-client.cmd —— 便携模式下的启动脚本（设置 DOTNET_ROOT）
launcher.json 只在玩家还没有自己的设置时生效。一旦他在设置页点过「保存」， 就以 %LOCALAPPDATA%\0verClient\settings.json 为准 —— 玩家的修改不会被预设覆盖。

只想做服务器端：.\build-dist.ps1 -Target server -Aot。

NativeAOT 只适用于服务器端。 WPF 客户端不支持 AOT，所以 -Aot 必须配 -Target server；客户端用 -SelfContained 或 -Portable。 客户端体积下不来是 WPF 的固有限制（它的运行时无法裁剪）。
客户端为什么这么大，怎么变小。 171 MB 里 76.3 MB 是 .NET 运行时、94.4 MB 是 WindowsDesktop（WPF）运行时、我们自己的程序只有 0.3 MB。 WPF 既不能裁剪也不能 AOT（SDK 会直接拒绝：NETSDK1168），所以两个实测可行的办法是：
  • 框架依赖 → 280 KB，代价是玩家要装一次 .NET 10 桌面运行时（缺失时程序会自己打印官方下载链接）
  • 单文件 + 压缩 → 59 MB，零依赖（首次启动多花约 9 秒解压 8 MB 原生库，磁盘约 67 MB）
原来的 -Portable / 文件夹式 -SelfContained（171 MB）已被单文件压缩版全面取代。 详见 guide.html。
为什么便携包有 77 MB？ 因为里面 99.6% 是 .NET 运行时，程序本身只有 290 KB。 运行时不能只取用到的部分 —— 要按需裁剪就得用 AOT 或裁剪编译，这正是上面两个模式存在的理由。

注意：压缩 ≠ 变小。 单文件压缩只减小传输体积，运行时首次启动时会解压到临时目录， 磁盘占用不变。只有 AOT / 裁剪才是真的把内容去掉。

打包会默认剥掉 .pdb。 调试符号在目标机上没有用，而 NativeAOT 的 .pdb 可能比程序本身还大（实测 9.7 MB 符号 vs 2.1 MB exe，所以"11.79 MB"里有 83% 是符号）。 需要排查崩溃时加 -KeepSymbols。
-Aot / -Trimmed / -SelfContained 需要从 nuget.org 下载包， 必须联网一次。-Aot 还需要 MSVC 工具链（装了 Visual Studio 就有）。 如果开发机不能上网，用 -Portable。

6. 迁移到另一台服务器

这是做成 exe 的主要目的。换服务器只需要三步：

  1. 在新服务器上放好两个文件夹 
    C:\0verclient\        ← dist\server 的内容（exe + run-server.cmd [+ runtime]）
C:\0verclient\site\   ← 站点文件（index.json + games）
  2. 双击 run-server.cmd（或手动跑 0verClient.Server.exe --root ... --port 8787 --add-firewall-rule）
  3. 放行新服务器的 8787 端口（云安全组 + 机器防火墙）
换了 IP 就必须重新打包站点。 index.json 和 manifest.json 里存的是绝对 URL，地址变了必须让它们跟着变： 
:: 1) 改 ServerIP.txt 为新服务器 IP
:: 2) 重新打包（会自动读 ServerIP.txt）
.\publish-testpack.ps1 -SkipCheck
:: 3) 把 build\site 传到新服务器
服务器程序启动时会自动检查这一点，发现清单指向 127.0.0.1 就会警告。

如果新服务器上没有 .NET 运行时，用 -Portable 或 -SelfContained 打包的 dist\server —— 那种包不依赖任何已安装组件。

7. 日常更新游戏

:: 打包一个真实游戏目录
.\tools\Publish\bin\Debug\net10.0-windows\Publish.exe `
  --game "D:\Games\我的游戏" --id mygame --name "我的游戏" --version 1.0.0 `
  --base-url http://YOUR_SERVER_IP:8787 --out build\site

:: 把整个 site 传到服务器（覆盖）
:: 启动器里点「刷新游戏库」，再点「安装」

index.json 是合并而不是覆盖，所以游戏可以一个一个加，测试包不会被删。

玩家侧点「安装」时，启动器会逐个文件比对 大小 + sha256，只下载不一致的文件， 一致的文件用硬链接从现有安装复用（瞬间完成、不额外占盘），全部校验通过后才原子切换到新版本。

传大文件不要用剪贴板。用 mstsc →「显示选项」→「本地资源」→「详细信息」→ 勾选本地磁盘，然后在远程会话里从 \\tsclient\C\... 复制。

8. 目录与组件职责

路径是什么
src/0verClient.Core/引擎：清单解析与信任链、下载（Range 续传）、安装事务、进程守护、路径与 URL 防护。不依赖任何 UI，可无头测试
src/0verClient.App/WPF 客户端（半透明圆角窗口、卡片悬停描边）
src/0verClient.Server/服务器端程序：把站点目录用 HTTP 提供出去
tools/Publish/把游戏目录打包成静态站点（算 sha256、生成清单、更新索引）
tools/SmokeTest/无头自检：43 项检查覆盖整条安装链路
tools/serve-site.ps1零安装的 PowerShell 版内容源（服务器上不想放 exe 时的备选）
tools/check-server.ps1服务器六层健康检查
tools/DevServer/本地开发用内容源（现场生成清单，跑 demo）
samples/DemoGame/示例"游戏"（独立 WPF 程序）
samples/TestPack/占位测试包（2.5 KB，验证从服务器下载）
run-demo.ps1本地一键 demo
publish-testpack.ps1读取 ServerIP.txt 并打包测试包，打印后续步骤
build-dist.ps1产出可分发的服务器端与客户端

10. 故障排查

现象原因怎么办
游戏库空的，提示"读取索引失败" 内容源没在跑 服务器上启动 run-server.cmd；界面中间会有「重试」按钮
提示"这个内容源里还没有游戏" 索引读到了但里面 0 个游戏；最常见是地址填成了某个游戏的 manifest.json 地址要以 /index.json 结尾。新版客户端会直接指出这一点
报「URL 主机不在白名单内」 设置页两个条件没同时满足 勾选「允许明文 http」并且把主机写进白名单（只填 IP，不带 http:// 和端口）
报「内容源地址自相矛盾」 服务器上是本地地址打的包 改 ServerIP.txt 后重新 publish-testpack.ps1，重传 site
服务器启动报端口被占用 旧的服务器实例还在跑 netstat -ano | findstr :8787 → Stop-Process -Id <PID> -Force
浏览器一直转圈 云安全组没放行，或服务没在跑 先在服务器上自测 127.0.0.1:8787；通的话就是安全组
报「清单哈希校验失败」 只传了 index.json 没传 manifest.json 整个 site 目录一起传
服务器报"禁止运行脚本" Windows Server 默认执行策略 Restricted 用 exe 版本，或加 -ExecutionPolicy Bypass

11. 当前能力与已知限制

已验证

43 项无头自检全过：路径与 URL 防护、清单哈希、下载、断点续传、增量安装（硬链接）、 事务化提交、.cmd 入口的真实进程启动与回收。

界面

半透明圆角窗口、侧边栏、卡片悬停描边、进度条、空状态引导、失败原因对话框。 XAML 由 --selfcheck 自动验证，视觉观感需人工确认。

尚未做

manifest 签名。现在明文 http 下 index.json 可被中间人替换， 哈希与清单同源挡不住。计划用内置 ECDsa P-256 签名、公钥硬编码进客户端。

扩展性

并发下载（目前逐文件串行）、封面图、zip 打包组、启动器自更新、SQLite 本地库。
